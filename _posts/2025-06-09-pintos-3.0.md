Pintos 本身已经实现了基础的虚拟内存, 我们需要增加一些新东西. 不幸的是,
我们增加的新东西可能会让整个程序行为变的更加奇怪, 增加了 debug 难度.

## Proj3A Demand Paging

### 明确需求

当我们不修改任何代码的时候, 我们看到 `page-linear`, `page-merge-*` 的测试结果是
Run didn't produce any output. 看上去整个应用程序都没有被执行? 猜想归猜想, 启动 gdb 才能发现真相.

![cgdb1](/assets/images/CS130/proj3_task1.1.png)

实际确实如此, 由于用户程序开了一个 2MB 大小的静态数组, 这导致 `zero_bytes=2099004`, 我们的
`load_segment()` 不断调用 `palloc_get_page()`. 然而用户内存池只有 1MB 大小, 自然不够用.

简单来说, 我们要允许应用程序开比较大的全局数组.

### 分析

如果应用程序申请很大的静态空间, 我们不立刻拒绝它, 那么只能欺骗他咯. 也就是申请内存的时候不分配内存,
用一个 page table 来管理所有应用程序申请过的内存. 如果程序试图访问这个位置, 由于我们之前欺骗了它,
必然会造成 page fault, 这个时候在试着给它分配一个 frame.

就算采用了延迟加载, 内存还是有用完的时候, 这时就可以考虑使用硬盘的空间. 这个空间来自硬盘 swap 分区,
我们给自己电脑装系统的时候可能就会创建一个. 可以考虑建立一个 swap table 来管理, 其核心功能就是
`swap_in()`, `swap_out()`. 当然内存依旧可能用完, 但是这里我们似乎不用考虑?

这里东西看上去比较多, 有两个比较常见的顺序: 一是从 frame table 开始, 自底向上搭建; 二是从 supplemental
page table 开始, 自顶向下搭建. 看上去[官方文档][1]给出的顺序是第一种.

[1]: https://pkuflyingpig.gitbook.io/pintos/project-description/lab3a-demand-paging/suggestions

把 frame table (不含 eviction), supplemental page table, swap table 相对独立的完成后可以试着拼在一起,
请小心的处理 page fualt, 尤其是在前一个项目中利用 page fault 来处理非法用户输入情况时. 至于
evicion, 减少 LRU 的算法可以暂时不考虑, 随便选一个暂时无所谓, 关键是正确的释放资源.
到了这里我们应该只有 `vm/` 底下的测试点会不通过, 而且可以通过 `page-linear`.

我们还需要考虑一下并发情况. 比如说 `page-parallel`, 它同时创建了几个线程跑 `page-linear`.

最后就是认真实现 eviction 策略, 可以选择时钟算法.

### Frame Table

对于 frame table, 个人认为它是对 `palloc_get_page()`, `palloc_free_page()` 加了一层封装,
它的核心是获取空闲内存, 难点在于无法通过 `palloc_get_page()` 分配内存的时候.

第一步是找到合适的 frame 来释放,关键是找到合适的 page replacement algorithm, 根据官方文档的要求,
我们选择的算法不应该劣于 "second chance" 或 "clock" 的简单变式.

第二步是把它写入 swap 分区, 实现了 swap table 之后就比较简单.

第三步是正确清理原 frame 所绑定的数据, 也就是所对应的 supplemental page, 以及调用
`pagedir_clear_page()`.

### Swap Table

首先介绍一下创建一个 n-MB 大小 swap 分区的方法 `pintos-mkdisk swap.dsk --swap-size=<n>`.

我们需要把整个 swap 分区分割成一个个小块的 swap slots, 那么第一个挑战就是访问 swap 分区,
方法是利用 `devices/block.c`. 我找到了几个有用的函数 `block_get_role()`, `block_size()`
`block_read()`, `block_write()`. (关于 block, sector 这些概念, 可以试着去问 AI 来理解)

我只打算实现 `swap_init()`, `swap_out()`, `swap_in()` 而不像我在网上搜到的参考代码一样来一个
`swap_free()`. 理由是我可以通过临时 `palloc_get_page()` 从 kernel pool 里面拿一页内存作为
buffer 来不断 `swap_in()` 就可以实现 `swap_free()` 的功能. 我希望精简接口.

### Supplemental Page Table

首先我们应该知道 pintos 有管理 page table 的代码, 位于 `process/pagedir.c` 里面, 所以标题使用
supplemental 来加以区分. 还有一种实现方法是可能是利用现有的 page table entry 中留给操作系统的 3bit
不过官方文档表示这是 advanced students only 的选项, 我也不是特别有想法.

在 `load_segment()` 中, 我们只需要 lazy load 一页数据.

等到 page fault 发生, 我们可能就需要 full load 该页数据了. 加载可能有两种来源, 一种是从文件中读取,
一种是从 swap 分区读, 我们可以用 `enum page_status` 来控制其状态.

关于 `struct page`, 如果用哈希表来管理的话, 我们的哈希需要考虑虚拟地址与其拥有者的 tid,
如果拥有者不存在我的方法是取 `TID_ERROR`.

### Accessing User Memory

例子来自[这里][2], 看上去[官方文档][3]也有提及. 如果一个进程 A 正在执行 `read()` 系统调用,
且获取了 `filesys_lock()`, 它下一步由于 buffer 缺页需要获取 `frame_lock()`; 另外一个进程 B
触发了 `page_fault()`, 并拿到了 `frame_lock()`, 它下一步由于需要 evict 需要获取
`filesys_lock()`. 这时会发生死锁.

一种可行的解决方案是不长时间持有 `frame_lock()`, 通过 `frame_set_pinned()` 来进行并发控制.

[2]: https://astatineai.github.io/ShanghaiTech-CS130-Project/pintos/proj3/#task-4-accessing-user-memory
[3]: https://pkuflyingpig.gitbook.io/pintos/project-description/lab3a-demand-paging/your-tasks#task-2-accessing-user-memory

### Sharing

这一部分属于 extra credit, 一种实现的思路是试着让多个 page 共享一个 frame,
至于确定两个页可以共享的方式是比较拥有它们的线程的 `name` 字段而不是直接比文件指针, 当然
`ofs` 也应该相同. 另外 `file` 与 `ofs` 唯一对应的时候, 其实可能会同时出现 read-only 与
writable 的两部分.

### 一些问题

- pintos 的公开测试点应该不包含 approximates LRU 的 eviction 算法.
- pintos 的公开测试点应该不包含 unmodified pages should never be written to swap 这一要求.
  写的时候注意这一情况: 某一页数据被修改之后 evict, 它从 swap 分区读回来之后, 没被修改再次被 evict,
  我第一次写没注意它的 dirty 值在写入读取 swap 分区的过程中被重置了.
  另外我还写了一个针对这一要求的测试.

## Proj3B Mmap Files

### Stack Growth

如果我们在 `page_fault()` 中遇上类似于访问栈空间的行为, 我们应该将其视为合法访问并分配更多栈空间.
那么问题有两个: 判断当前需要栈增长; 进行栈增长.

第一个问题需要注意直接从 `struct intr_frame` 里面获取的 esp 位置其实不一定指向用户栈指针,
我们可能需要在每个线程内部维护对应的数据.

另一个问题需要注意 stack 占用的内存也可以 evict, 所以在 stack growth 的时候不能无脑拿出新的一页,
它可能存在于 swap 中.

### Memory Mapped Files

也许是最省心的一个部分? 简单来说就是把 file 映射的内存全部 lazy load, 或者把这些 page 写回文件系统.

- 检测 map 内存区域重叠, 一种方式是遍历可能被占用的地址, 查看是否已经被映射.
- 文件长度不是 `PGSIZE` 的倍数的时候, 末尾补零即可, 但不应该把补上的零写回文件系统.
- 传入的 `fd` 对应的文件可能被关闭, 需要 `file_reopen()` 来续命, 最后用 `file_close()` 关闭即可.
- `mapid_t` 只需要在一个线程之内唯一即可, 如果对每个线程记录独立的 `next_mapid` 就不需要加锁.
- 进程退出的时候不要忘记释放这些资源, 我的方案是对当前线程的 `nex_mapid` 不断递减并试着 `unmap()`.

## 补充

- 关于并发情况的问题, 可能要在性能比较差劲的电脑上 (或者打开 gdb 调试) 才会遇上.
- 其实这里的并发控制, 除了加锁还有其他方式. 至少我认为 frame table, swap table 之类的都是
  reader-writer 模型, 也可以使用条件变量来控制.
- 如果你在 `page-fault` 中发现错误地址位于 0xcccccccc 附近, 这个问题可能是 use-after-free,
  这是因为 `threads/palloc.c` 与 `threads/malloc.c` 会在我们 `free()` 的时候把它们把地址修改为
  `0xcc`.
- 如果你在 debug 的时候经常因为 pintos-debug: a page fault exception occurred in user mode
  而停在 `0xc00228ca in intr0e_stub ()` 的话, 可以试着把模拟器从 bochs 切换到 qemu.

## 随便写的附加测试

### ex-test2

测试 unmodified pages should never be written to swap 的要求, 思路是创建一个大的静态数组,
然后扫一遍不修改. 就算 swap 比较小我们也不应该崩溃.

```bash
cd ../../examples/ && \
make && \
cd ../vm/build/ && \
pintos --filesys-size=2 --swap-size=0.5 -p ../../examples/test2 -a test2 \
-- -q -f run test2
```

```c
/* test2.c
   Create a static array of 3MB, only read it instead of writing to it.
   The swap cannot be full if we run pintos with a relatively small swap size.
*/

#include <stdio.h>
#include <syscall.h>

#define SIZE (4 * 1024 * 1024)

static volatile char read_only[SIZE];

int
main (void)
{
  printf ("test2: init\n");

  for (size_t i = 0; i < SIZE; i++)
    if (read_only[i] != 0)
      {
        printf ("test2: read-only array was modified\n");
        return EXIT_FAILURE;
      }

  return EXIT_SUCCESS;
}
```
