## Task1: Indexed and Extensible Files

### 明确需求

目前 pintos 的文件大小不可增长, 而且它会占用磁盘连续的扇区. 我们需要重新设计 `struct inode`,
来让文件大小变化更加容易, 并且不使用连续空间.

先以 `grow-root-lg` 为例, 它试着创建 50 个文件, 但是创建到第 14 个文件出现了
`(grow-root-lg) create "file14": FAILED` 错误. 进一步分析, 问题出现在 `dir_add()` 接近最后的
`inode_write_at (dir->inode, &e, sizeof e, ofs) == sizeof e` 只写入了 0 byte, 它的原因是
`root->inode` 已经写满了, 然而我们目前无法扩展文件大小.

### 分析

我们可以参考 Unix 的 inode 设计, 我们只需要考虑最大 8MB 的文件, 那么设置一个 `doubly_indirect`
指针就足够了. (如果只是面向拿分编程的话, 其实不需要 `direct` 与 `indirect`,
但是这两个在实际场景中还是有用的)

在修改了 `struct inode` 之后, 我们需要修改 `byte_to_sector()`, `inode_create()`, `inode_close()`,
并且在 `inode_write_at()` 满足 `offset + size > inode->data.length` 的时候申请新的 sector.

### 实现

```c
struct indirect_block
{
  block_sector_t sectors[128]; /* Pointers to data blocks. */
};

/* On-disk inode.
   Must be exactly BLOCK_SECTOR_SIZE bytes long. */
struct inode_disk
{
  off_t length;                   /* File size in bytes. */
  block_sector_t direct[10];      /* Direct pointers to data. */
  block_sector_t indirect;        /* Indirect pointer to data. */
  block_sector_t doubly_indirect; /* Doubly indirect pointer to data. */
  unsigned magic;                 /* Magic number. */

  /* Not used. */
  uint8_t unused[BLOCK_SECTOR_SIZE - sizeof (block_sector_t) * 12
                 - sizeof (off_t) - sizeof (unsigned)];
};
```

只完成这个 Task 的话, 这样定义数据结构即可 (虽然下面 Task2 实现的时候还会修改它).
因为 `doubly_indirect` 需要套两层, 代码组织不好会变得很丑陋. 资源获取时候的 bug
直接导致无法通过测试点, 相对好检查; 资源释放时候的内存泄漏相对更隐蔽, 最好多检查一下.

关于最后 `unused` 的分配, 我没有想到特别好的办法, 但是直接减去 `sizeof` 不见得是一个好想法,
因为结构体内成员位置在内存对齐的时候可能会加入一点偏移.

## Task2: Subdirectories

### 分析

这里主要围绕 5 个系统调用展开. 这里我打算把目录当作文件来看到, 也就是 `fd` 永远对应文件,
但是里面 `file->inode` 设置一个 `is_dir` 来区分. 但是我必须指出, 这其实是我的一个偷懒的做法,
这让我在实现 `readdir()` 的时候确实遇上了一点困难.

最后原有的系统调用需要更新, 更新的方式主要还是修改 `filesys_open()`, `filesys_close()`,
`filesys_remove()`. 需要注意 `filesys_remove()` 对于删除文件夹的行为与删除文件不一致.

### 实现

首先是 `userprog/syscall.c` 里面的核心逻辑:

- `isdir(fd)`: `inode_is_dir(file_get_inode(query_file(fd)));`
- `inumber(fd)`: `inode_get_inumber(file_get_inode(query_file(fd)));`
- `readdir(fd, name)`: `filesys_readdir(query_file(fd), name);`
- `mkdir(dir)`: `filesys_create(dir, 0, true);`
- `chdir(dir)`: `filesys_chdir(dir)`

#### 路径的解释

这是官方文档的几个说明.

- `a//b` 等价于 `a/b`, 多个连续正斜杠会被当作一个解释.
- `/../x` 等价于 `/x`, 因为根节点的父节点还是根节点.
- `/x/` 如果 `x` 是一个文件夹没有问题, 如果是文件应当拒绝.

下面是我的方案.

先做路径合法化, 把 `////` 换成 `/`, 并去掉文件末尾的 `'/'`.

- `mkdir ""` -> `buf = ""`, 不允许.
- `touch ""` -> `buf = ""`, 不允许.
- `mkdir "/"` -> `buf = ""`, 不允许.

接着分割 `path` 与 `file`, 如果 `path` 为空则设为 `.`, 拒绝 `file` 为空的情况.

- `mkdir "home"` -> `path = ""`, `file = "home"`.
- `mkdir "/home"` -> `path = "/"`, `file = "home"`.
- `touch ".bashrc/` -> `path = ".bashrc"`, `file = ""`, 不允许.
- `touch ".bashrc` -> `path = ""`, `file = ".bashrc"`.
- `touch "/.bashrc"` -> `path = "/"`, `file = ".bashrc"`.
- `touch "root/.bashrc` -> `path = "root/"`, `file = ".bashrc"`.

这一部分建议独立成函数并在 pintos 之外写几组单元测试. 我的实现接口为
`bool split_path(const char *name, char *path_name, char *file_name);`
这个时候可以选择给 `path_name` 与 `file_name` 写两个 `malloc()`, 调用者需要两次 `free()`.

#### `filesys_create()` 的一些细节

关于 `filesys_create()`, pintos 的 `filesys_create()` 的核心部分是这样的

```c
  struct dir *dir = dir_open_root ();
  bool success = (dir != NULL && free_map_allocate (1, &inode_sector)
                  && inode_create (inode_sector, initial_size)
                  && dir_add (dir, name, inode_sector));
```

~~其实这样写我感觉是 bad practice, 四个条件放一起, 如果哪一步真的 fail 了不太容易定位具体问题~~

我做了两处修改, 第一处是 `inode_create()` 多传入了 `bool is_dir` 与 `parent_sector`; 第二处是在
`dir_open_root()` 与下面 `dir_add()` 之间加一个 `dir_walk()`. 试着把 `name` 中属于目录的部分给去掉, 并更新 `dir`.

由于文件路径可以是绝对路径或者是相对路径, 我们需要在每个线程里面记录 `cwd`, 不建议记录
`struct dir *`, 一方面会给初始化带来难度, 另一方面 `dir_open_cwd()` 最好行为与 `dir_open_root()`
要类似.

如果能实现 `filesys_create()` 并且函数分割合理的话, 修改 `filesys_open()` 与 `filesys_remove()`
应该不是太难.

#### `filesys_readdir()` 的一些细节

这里讲一下 file 与 dir 之间的转换, 它们的结构除了有 `struct inode` 之外, 还有一个 `pos`,
那么转换的时候不可以直接调用 `dir_open()`, 因为它会设置 `pos = 0`. 正确的做法应该是
`dir->pos = file_tell (file);`. 并且在关闭的时候 `file_seek(file, dir->pos);` 来同步修改.

## Task3: Buffer Cache

**警告**: 官方 reference solution 中 `filesys/cache.c` 写了 473 行, 我们实现所用代码行数远小于
473 行, 不出意外有漏掉的 corner case.

### 明确需求

由于 CPU 无法直接访问磁盘, 需要通过 PCIe 总线才可以通信, 这是很慢的. 一个常用的加速方式就是 cache,
这个概念我们应该不是太陌生.

### 分析

我们的 cache 应该只是 filesys 与 device 直接新增的一个间接层, 比较朴素的想法是让 `cache_read()` 与
`cache_write()` 的接口设计的同 `block_read()`, `block_write()` 完全一致. 可惜官方文档要求我们去掉
`inode_read_at()` 与 `inode_write_at()` 里面的 "bounce buffer", 我们可能需要支持更灵活的部分读写,
那就不可避免的需要增加一些内容.

当然除了这两个, 我们还需要 `cache_evict()` 作为 cache miss 的情况, 具体算法与前面 frame evict 类似.
我们 cache 的问题是突然断电数据会丢失, 为了减少数据丢失的影响, 我们最好定期 `cache_flush()`,
但是它不能直接在 `devices/timer.c` 中的 `timer_interrupt()` 中被唤醒, 因为那个时候我们处于外部中断,
无法获取可能需要的锁. 解决方案可能是创建一个新的线程, `cache_flush()` 后接着 `timer_sleep()`.

但是我们创建的线程最好不要死循环, 万一关机到一半 flush 了, 可能会有一些问题. 由于 pintos 是单核心
(这个限定是必要的) 环境, 我们设置一个 `bool flush_done`, 只存在一次 `flush_done = true` 没有多次写,
也许可以安全的通知我们的 flush 线程.

还有一个需求是 read-ahead, 这里不应该阻塞发出请求的线程, 需要一个额外的线程负责读取. 一种方案是,
维护一个全局链表, 每次 `inode_read_at()` 读取文件的时候, 找到这个文件下一个 512B 的 sector
(如果有的话, 没有就忽略), 往全局链表加入这个信息, 调用 `sema_up()` 唤醒额外线程.

### 验证

虽然这个 task 不直接对应测试点, 但是我们可以观察 `tests/filesys/base` 底下本来就能通过的测试点的
`*.output` 中 (filesys) 部分的 read-write 次数变化来判断.

## Task4: Synchronization

### 分析

根据要求, 单个文件需要允许并发读, 但只能一个进程写, 这让我们想到读写锁, 那么可以先实现一下
`struct rwlock`.

先思考一下有哪些部分可能有 data race:

- `struct inode` 以及对它的操作, 不过注意一下 `inode_read_at()` 与 `inode_write_at()` 都需要访问
  `inode_length()`, 与 `byte_to_sector()`. 我们不应该让一个线程在持有锁的时候再次试图拿锁,
  所以可以添加一个 `inode_length_unlocked()`, 与 `byte_to_sector_unlocked()`.
- `static struct list open_inodes` 作为全局变量, 如果要遍历它, 最好需要上锁.
- 关于硬盘的读写, 在 `block_read()`, `block_write()` 的注释中我们知道现有代码已经处理好同步问题了.

### 实现

对于 `struct inode` 的操作, 需要注意这种情况: 两个线程同时操作一个 inode, 一个在 `inode_reopen()`,
而另一个在 `inode_close()`, 很有可能发生 use-after-free. 我的解决方案是设置一个全局
`inode_reopen_lock()`, 让这两种操作无法并发. 个人认为这个开销是可以接受的, 文件系统最慢的就是 IO,
然而这两个函数本身不会等待 IO, 所以可以接受访问全局锁.

## 补充

- 这里说一个特别蠢的 bug: 我在实现不能关闭非空目录的功能时, 打算在 `struct inode_disk` 里面记录一个
  `file_cnt`. 但是我没有意识到同一个 sector 在内存里会有多个不同的 `struct inode`,
  修改了一个但更新不写回缓存, 另一个是不会知道变化的.
- `READDIR_MAX_LEN` 最好不要超过 100 太多, 不然在执行 `tar` 的时候会因为
  `dir_len + 1 + READDIR_MAX_LEN + 1 > file_name_size` 而失败.
- 在实现 cache 的时候, 如果之前 proj2: userprog 依靠 page fault 来处理非法指针, 这里 `cache_read()`
  `cache_write()` 就可能转入 page falut 终止程序, 要记得释放可能获取的锁.

## 随便写的附加测试

### ex-test3

测试一下从文件 EOF 后面读取信息的时候是否会让内核崩溃.

```bash
cd ../../examples/ && \
make && \
cd ../filesys/build/ && \
pintos -k -T 60 --qemu --filesys-size=4 --swap-size=4 -p \
../../examples/test4 -a test4 -- -q -f run test4
```

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <syscall.h>

#define MAX_FILE_SIZE (8 * 1024 * 1024) /* 8 MB */

char buf[512];

int
main (void)
{
  printf ("test4: begin\n");

  create ("file", 2000);
  int fd = open ("file");
  for (size_t ofs = 0; ofs <= MAX_FILE_SIZE + 200; ofs += 2000)
    {
      seek (fd, ofs);
      int __attribute__ ((unused)) _ = read (fd, buf, sizeof (buf));
    }
  close (fd);
  printf ("test4: success\n");

  return EXIT_SUCCESS;
}
```
