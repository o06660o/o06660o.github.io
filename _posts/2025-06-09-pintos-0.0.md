上海科技大学操作系统的课程项目是两人组队完成整个 pintos, 这几篇文章记录了我当时的一些想法.
代码放在 [Github 仓库](https://github.com/o06660o/CS130-25Spring-Project), 能够通过所有公开测试点
(不保证任何机器下表现一致), 但是学校 hidden test 挂了一个.

## 环境搭建

### 安装

这里是[环境要求](https://web.stanford.edu/class/cs140/projects/pintos/pintos_12.html),
其实我们可以直接选择北京大学的 docker 镜像.

```bash
sudo systenctl start docker
sudo docker run -it pkuflyingpig/pintos bash
```

安装完毕之后输入 `exit<Enter>` 退出容器. 复制一份 pintos 的源代码

```bash
git clone git://pintos-os.org/pintos-anon
```

### 启动 docker

每次运行的时候需要执行命令 (记得修改 `source=` 后的路径)

```bash
sudo docker run -it --rm --name pintos \
--mount type=bind,source=/absolute/path/to/pintos/on/host/machine,target=/home/PKUOS/pintos \
pkuflyingpig/pintos
```

这个命令会启动一个新的容器, 并将本地的 `pintos` 文件夹挂载到容器的 `/home/PKUOS/pintos/` 目录下.
这样我们可以在容器外部修改文件, 在容器内部编译运行.

### 检查环境搭建是否正常

上一步执行完成后会看到一个类似于 `root@00388754f57d:~#` 的提示符, 然后输入下面的指令.

```bash
cd pintos/src/threads/
make
cd build
pintos --
```

如果看到了

```text
Pintos hda1
Loading............
Kernel command line:
Pintos booting with 3,968 kB RAM...
367 pages available in kernel pool.
367 pages available in user pool.
Calibrating timer...  32,716,800 loops/s.
Boot complete.
```

那么 Pintos 成功启动了, 接下来按 `<Ctrl-c>` 退出. (如果传入参数 `-q` 就不需要手动退出)

这里的 pintos 是什么? 个人认为, 它是 `src/utils/` 里面的一个 `perl` 脚本, 它通过 qemu 或者
boches 作为模拟器来让 pintos 的源代码能够在我们的机器上运行.

### 编译运行

我们一共有四个 proj, 对应四个目录, 每个目录下都有一个 `Makefile`, 虽然它们的内容一样,
但要注意边上还有不一样的 `Make.vars`. 在做对应 proj 的时候需要在对应目录下用 `make` 来编译,
编译完成之后可以 `cd build` 然后通过 `pintos` 命令来运行.

`pintos` 命令的格式是 `pintos [OPTION...] -- [ARGUMENT...]`, 中间有点奇怪的 `--` 是用来分割
`OPTION` 与 `ARGUMENT` 的. `OPTION` 可以在 `pintos -h` 中查看, 而 `ARGUMENT` 会被传递给
Pintos Kernel.

举个例子, 我们想要先跑跑看第一个 proj 的测试, 那么有下面的命令

```bash
cd pintos/src/threads
make check
cd build
pintos -- -q run alarm-multiple
```

`make` 命令中 `check` 表示运行所有测试. `pintos` 命令中 `-q` 是运行完成后退出,
`run alarm-multiple` 是运行一个特定的测试.

如果要编译并运行特定测试可以通过 `make tests/threads/alarm-multiple.result` 来实现.
输出 test result is up-to-date 可以执行 `rm tests/threads/alarm-multiple.output`,
也可以选择执行 `make` 命令中显示的 `pintos` 开头的一长串命令.

### 调试

编译好代码就可以调试了, 只不过命令 `pintos` 需要一个 `OPTION`: `--gdb`.
接着我们还需要再打开一个终端并输入 `docker exec -it pintos bash` 进入 `docker` 容器.

```bash
cd pintos/src/threads/build
pintos-gdb kernel.o
```

在打开的窗口中输入 `debugpintos`, 熟悉 gdb 的人可以很快上手.

## 我的个性化配置

### pintos-gdb 的自定义

默认情况下, `cgdb` 中水平分隔了两个窗口, 可惜的是 `pintos-gdb` 使用的 `cgdb` 版本可能比较老,
并不能把它从水平分割变成竖直分割. 但是新版本的 `cgdb` 可以实现这个需求,
那么我们需要想办法利用外部的 `cgdb` 来调试容器内运行的程序.

那么我们在容器运行的时候添加参数 `-p 1234:1234` 映射端口, 正常执行 `pintos --gdb --`,
然后在本地执行 `cgdb kernel.o` 输入 `target remote localhost:1234` (其实就是 `debugpintos`),
这样我们就可以用最新的调试工具来 debug 了.

修改 `~/.cgdb/cgdbrc`, 写入 `set winsplitorientation=vertical` 就能够实现我刚刚的需求了.
更多配置可以打开 `cgdb` 输入 `:help` 查看.

还有一个问题, `pintos-gdb` 有一些 Godmar Back 定义的宏, 它们在一般的 `cgdb` 中不存在.
这当然是有解决方案的,

虽然这样会丢失一些用户定义好的宏, 但是 `pintos-gdb` 定义的宏位于 `src/misc/gdb-macros`.
我们可以选择在 `.gdbinit` 中 `source /path/to/gdb-macros`
也可以直接在调用 `cgdb` 的时候 `-x /path/to/gdb-macros`

### 自动格式化代码

我推荐安装 `clang-format` 并在项目根目录下设置 `.clang-format` 文件,
里面写 `BasedOnStyle: GNU` 就差不多了.
具体使用可以查阅网上资料.

### 启动 LSP

虽然不使用任何补全并不影响你完成 pintos (实际上我做前两个 proj 就是用无补全的 neovim 完成的),
但我们确实希望能够使用 `clangd` 这样的现代化工具. 那么我们需要生成 `compile_commands.json`
它才可以理解整个项目. 先安装 bear, 然后在 `src/threads/` 下面执行

```bash
make clean
bear -- make
```

我到这一步似乎就已经好了, 如果 clangd 无法正常工作的话可以在 clangd 中添加参数
`--compile-commands-dir=src/threads/build`.
可以看 [这里](https://clangd.llvm.org/installation) 来进一步处理问题.

你可以把 `compile_commands.json` 放在一个自己喜欢的位置, 我打算放入 `src/` 文件夹里面.

最后不要忘记修改 `.gitignore`.

```bash
cd pintos/src/threads/build
pintos-gdb kernel.o
```

这样我们就进入了 `pintos-gdb` 的界面, 输入命令 `debugpintos`,
我们就连接到了前面 `pintos` 命令创建的模拟器了.
这其实是 `cgdb`, 具体怎么使用这里不赘述.

### 使用 ANSI 转义序列

pintos 运行时候的输出只有白色, 像我这种视力不好的人很有可能会漏掉关键信息, 这时候就可以尝试使用
ANSI 转义序列.

举个例子, `printf ("\033[31mBoot complete.\n\033[0m");` 这样会输出一个更醒目的红色 Boot complete.
关键就是前后的 `\033[31m`, `\033[0m`.

> [!NOTE]
> 只有输出目标是终端的时候, ANSI 转义序列才会被正确解析, 如果你希望看输出的文件没有多余字符的话,
> 可以用 `isatty(fileno(stdout))` 来检测.

简单来说, `\033[显示方式;前景色;背景色m` 是常见的 ANSI 转义序列格式. 而具体内容可以看
[这里](https://zh.wikipedia.org/zh-hans/ANSI%E8%BD%AC%E4%B9%89%E5%BA%8F%E5%88%97#%E9%80%8).

## 补充

- 如果不希望每次输入命令的时候加 `sudo`, 可以执行 `sudo usermod -aG docker $USER` 将当前用户加入
  `docker` 组. (注销后生效)
- 如果启动命令过长可以设置缩写 `alias pintos-run="sudo docker run xxx"`.
- 如果出现 `Could not fetch register "orig_eax"; remote failure reply '14'` 之类的错误可以把模拟器
  从 qemu 修改为 bochs.
